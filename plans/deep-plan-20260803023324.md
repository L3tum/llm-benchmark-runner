# Deep Plan: Fix All Themed Review Issues

## Context

The LLM benchmark runner has 9 new benchmark modules (cruxeval, ruler, halubench, bbh, factbench, truthful_qa_gen, popqa, scifact, snli) that were flagged with 18 issues across 7 themed code reviews. This plan addresses every finding, prioritized by severity. The critical fix replaces unsafe Python subprocess execution in CRUXEval with Docker-isolated evaluation using the existing `DockerRunner` infrastructure.

## Approach

Implement fixes in three phases:

1. **Phase 1 (CRITICAL + HIGH):** Command injection, meaningless scoring, process-killing exits, prompt duplication
2. **Phase 2 (MEDIUM):** Null label handling, needle position accuracy, prompt injection fences, unit tests for scoring functions
3. **Phase 3 (MINOR):** Linting, dead code, DRY violations, synthetic fallback warnings, RNG replacement

**Key design decisions:**
- **CRUXEval Docker isolation:** Use existing `DockerRunner` + `DockerRunConfig` with security defaults (network none, read-only root, cap-drop ALL, memory 512m, timeout 30s). Pass untrusted data via `-e` env vars, never interpolated into shell strings. Fall back to exact string match if Docker is unavailable.
- **CRUXEval Repair scoring:** Execute the repaired code in Docker with the test input, capture stdout, and compare with ground truth. Same Docker security model.
- **Prompt fences:** Wrap all interpolated dataset values in XML fence tags (`<value>...</value>`) within the prompt template — lightweight, no new dependencies.
- **`std::process::exit(1)` replacement:** Return `Result<Vec<T>>` from loaders, propagate errors through `pre_execute()`.

## Detailed Requirements

### Phase 1: CRITICAL + HIGH

#### Fix 1: [CRITICAL] Command Injection in CRUXEval (`src/benchmarks/cruxeval.rs`)

**Current (lines 132-175):** `evaluate_prediction()` interpolates untrusted `predicted` and `ground_truth` into a Python script string via `format!("{:?}")`, then executes via `std::process::Command::new("python3").args(["-c", script])`. Even `{:?}` Debug formatting is not a sufficient sandbox — adversarial strings can break Python literal context.

**Fix:**
1. Replace `evaluate_prediction(predicted, ground_truth) -> bool` with `evaluate_prediction_docker(predicted, ground_truth) -> bool`
2. Write the normalization Python script to a temp file (not inline)
3. Use `DockerRunner` with `DockerRunConfig::new("python:3.11-slim", ...)`:
   - Pass `predicted` and `ground_truth` as env vars (`-e PREDICTED=...` and `-e GROUND_TRUTH=...`)
   - Mount the script as read-only
   - Command: `["python3", "/tmp/normalize.py"]`
   - Security defaults: `network_none: true`, `read_only_root: true`, `cap_drop_all: true`, `memory: Some("512m")`, `timeout_secs: 30`
   - Script reads env vars: `pred = os.environ["PREDICTED"]`, `gold = os.environ["GROUND_TRUTH"]`
4. **Fallback:** If Docker is unavailable (check `DockerRunner::image_exists()` or catch spawn error), fall back to exact string match only: `predicted.trim() == ground_truth.trim()`

**New code structure:**
```rust
fn evaluate_prediction(predicted: &str, ground_truth: &str) -> bool {
    // Fast path: exact match
    if predicted.trim() == ground_truth.trim() {
        return true;
    }

    // Try Docker-isolated Python evaluation
    match evaluate_prediction_docker(predicted, ground_truth) {
        Ok(result) => result,
        Err(e) => {
            eprintln!("  Docker eval unavailable ({}), using exact match fallback", e);
            false
        }
    }
}

fn evaluate_prediction_docker(predicted: &str, ground_truth: &str) -> Result<bool> {
    // 1. Write normalization script to temp file
    let script = r#"
import os, sys, ast
... (same normalization logic) ...
pred = normalize(os.environ["PREDICTED"])
gold = normalize(os.environ["GROUND_TRUTH"])
sys.exit(0 if pred == gold else 1)
"#;
    // 2. Create DockerRunConfig with env vars
    // 3. Run via DockerRunner::run()
    // 4. Return result.success()
}
```

**Dependencies:** Uses existing `DockerRunner` from `src/docker_runner.rs`. No new dependencies.

#### Fix 2: [HIGH] CRUXEval Repair Scoring (`src/benchmarks/cruxeval.rs`, lines 260-268)

**Current:** `!response_trimmed.is_empty() && response_trimmed.len() > 10` — any text >10 chars passes.

**Fix:** Execute the repaired code in Docker:
1. Write the model's fixed code to a temp file
2. Write the test input to a temp file  
3. Run in Docker: `python3 /tmp/fixed.py < /tmp/input.txt > /tmp/output.txt`
4. Compare captured stdout with ground truth
5. If Docker unavailable, mark as incorrect with diagnostic: "Repair scoring skipped — Docker required"

```rust
CruxEvalSubset::Repair => {
    match evaluate_repair_docker(response_trimmed, &item.input, &item.output) {
        Ok(result) => result,
        Err(_) => false, // Docker unavailable, mark incorrect
    }
}
```

#### Fix 4: [HIGH] `std::process::exit(1)` (6 files)

**Current:** `cruxeval.rs:126`, `halubench.rs:118`, `popqa.rs:104`, `snli.rs:149`, `scifact.rs:148`, `truthful_qa_gen.rs:87` — all call `std::process::exit(1)` on download failure.

**Fix:** Change each `load_*_dataset()` function signature from `-> Vec<T>` to `-> Result<Vec<T>>`. Return `Err(anyhow!("..."))` at the end of the download loop. In `pre_execute()`, propagate with `?`.

For `cruxeval.rs`, the return type change cascades but `pre_execute` already returns `Result<()>`, so it's a clean change. Same for all 6 files.

**Example change pattern:**
```rust
// Before
fn load_cruxeval_dataset(subset, max_items) -> Vec<CruxEvalItem> {
    ...
    std::process::exit(1);
}

// After  
fn load_cruxeval_dataset(subset, max_items) -> Result<Vec<CruxEvalItem>> {
    ...
    Err(anyhow!("Could not download CRUXEval dataset from any source"))
}
```

### Phase 2: MEDIUM

#### Fix 7: [MEDIUM] SNLI Null gold_label (`src/benchmarks/snli.rs`, lines 74-78)

**Current:** `unwrap_or("neutral")` assigns missing labels to "neutral".

**Fix:** Skip items with null gold_label entirely:
```rust
let gold_label = match val.get("gold_label").and_then(|l| l.as_str()) {
    Some(label) if label != "-" => label.to_string(),
    _ => continue, // skip items with missing or neutral labels
};
```

Apply this pattern in both the primary and fallback download blocks.

#### Fix 8: [MEDIUM] RULER Needle Position Inaccuracy (`src/benchmarks/ruler.rs`, lines 163-179)

**Current:** The word count tracking uses `(prompt.len() + value.len()) / 5 + 2` as an approximation after needle insertion, which shifts all subsequent word counts.

**Fix:** Build filler list first, then insert needle at the target position:
```rust
let num_fillers = target_word_count / words_per_filler;
let mut filler_list: Vec<String> = (0..num_fillers)
    .map(|i| fillers[i % fillers.len()].to_string())
    .collect();

// Insert needle at a random position in the list
let insert_pos = rng.gen_range(0, filler_list.len().max(1));
filler_list.insert(insert_pos, needle);

let context = filler_list.join(" ");
```

#### Fix 9: [MEDIUM] Prompt Injection Fences (all 9 benchmarks)

**Current:** All benchmarks use `String::replace("{placeholder}", &data_value)` directly, interpolating untrusted dataset fields into prompts.

**Fix:** Add an `escape_prompt()` helper in `src/shared.rs`:
```rust
/// Wrap a value in XML fence tags to mitigate prompt injection.
/// Usage: escape_prompt("user_value") -> "<value>user_value</value>"
pub fn fence_prompt_value(value: &str) -> String {
    format!("<value>{}</value>", value)
}
```

Then in each benchmark's `execute_one()`, fence the interpolated values:
```rust
// Example for scifact.rs
let prompt = user_prompt.replace("{claim}", &crate::shared::fence_prompt_value(&item.claim));
```

Apply to all 9 benchmarks where dataset values are interpolated into prompts. The system prompts already instruct the model to ignore embedded instructions, so the fences add a structural barrier.

#### Fix 13: [MINOR] Triplicate task construction in BBH (`src/benchmarks/bbh.rs`, lines 140-212)

**Current:** Three identical loops converting `BbhInstance` → `BbhTask` (cached path, primary download, fallback download).

**Fix:** Extract helper:
```rust
fn instances_to_tasks(instances: Vec<BbhInstance>, task_name: &str) -> Vec<BbhTask> {
    instances
        .into_iter()
        .map(|item| BbhTask {
            input_text: item.input,
            target: item.target,
            task_name: task_name.to_string(),
            few_shot_examples: item.few_shot_examples
                .unwrap_or_default()
                .into_iter()
                .map(|e| BbhExample { input_text: e.input, target: e.target })
                .collect(),
        })
        .collect()
}
```

Also remove unused `.enumerate()` index `i` from all three loops.

#### Fix 17: [MINOR] `String::from_utf8(Vec::from(bytes.as_ref()))` (cruxeval.rs, truthful_qa_gen.rs, snli.rs)

**Current:** Creates unnecessary intermediate `Vec<u8>` from `bytes::Bytes` before `String::from_utf8`.

**Fix:** Use `String::from_utf8_lossy(&bytes).into_owned()` or `String::from_utf8(bytes.to_vec())`. Since `bytes::Bytes` owns the data, `bytes.to_vec()` is the cleanest:
```rust
let content = String::from_utf8(bytes.to_vec())
    .expect("Failed to decode UTF-8");
```

## Reuse

- **`DockerRunner`** (`src/docker_runner.rs`) — Existing infrastructure for Docker container execution. Already used by `swe_bench.rs` and `terminal_bench.rs`.
- **`DockerRunConfig`** (`src/docker_runner.rs`) — Config struct with security defaults (network_none, read_only_root, cap_drop_all, memory limit).
- **`bytes::Bytes`** — `download_with_retry_bytes` returns this type; use `.to_vec()` for owned conversion or `&bytes` for borrowing.
- **`rand` crate** — Already in `Cargo.toml` at version 0.8. Use `SeedableRng` + `StdRng` for deterministic RNG.
- **`tempfile` crate** — Already in `Cargo.toml` for creating temporary files (Python scripts for Docker).
- **`Benchmark::pre_execute()` → `Result<()>`** — Already returns `Result`, so propagating download errors with `?` is clean.
